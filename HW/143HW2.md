# Data Class Code Smell

## a) ความหมายของ Code Smell นี้

**Data Class** คือ class ที่มีหน้าตาแบบนี้ - มีแต่ตัวแปรเก็บข้อมูล แล้วก็มี getter/setter เต็มไปหมด แต่ไม่มี method อื่นที่ทำอะไรเลย ก็คือเป็นแค่กล่องใส่ข้อมูลล้วนๆ

ทำไมมันถึงเป็นปัญหา?
- ถ้าเราเขียนแบบ OOP จริงๆ object ควรจะมีทั้งข้อมูลและความสามารถในการจัดการข้อมูลของมันเองด้วย ไม่ใช่แค่เป็นกล่องเปล่าๆ ให้คนอื่นมาดึงข้อมูลไปใช้
- พอ class มีแค่ข้อมูล logic ที่เกี่ยวข้องกับข้อมูลนั้นก็จะไปกระจายอยู่ใน class อื่นๆ ทำให้เวลาจะหาว่าอะไรทำงานยังไงต้องไล่ดูหลาย class
- ถ้าอยากแก้ไขพฤติกรรมอะไรสักอย่าง อาจจะต้องไปแก้หลายที่ เพราะ logic กระจัดกระจายไปหมด

## b) ตัวอย่างโค้ดที่เกิด Code Smell

ลองดูตัวอย่าง class ลูกค้าที่มีปัญหานี้:

```java
// class Customer มีแต่ข้อมูล ไม่มีอะไรทำเลย
public class Customer {
    private String name;
    private String email;
    private String phoneNumber;
    private int loyaltyPoints;
    
    // มีแต่ getter/setter เต็มไปหมด
    public String getName() {
        return name;
    }
    
    public void setName(String name) {
        this.name = name;
    }
    
    public String getEmail() {
        return email;
    }
    
    public void setEmail(String email) {
        this.email = email;
    }
    
    public String getPhoneNumber() {
        return phoneNumber;
    }
    
    public void setPhoneNumber(String phoneNumber) {
        this.phoneNumber = phoneNumber;
    }
    
    public int getLoyaltyPoints() {
        return loyaltyPoints;
    }
    
    public void setLoyaltyPoints(int loyaltyPoints) {
        this.loyaltyPoints = loyaltyPoints;
    }
}

// แล้วพอมี logic ที่เกี่ยวกับลูกค้า มันก็ไปอยู่ใน class อื่น
// ทั้งที่จริงๆ มันควรอยู่ใน Customer เอง
public class OrderService {
    // คำนวณส่วนลดตามคะแนน - ควรเป็นหน้าที่ของ Customer
    public double calculateDiscount(Customer customer, double orderAmount) {
        if (customer.getLoyaltyPoints() > 1000) {
            return orderAmount * 0.15;
        } else if (customer.getLoyaltyPoints() > 500) {
            return orderAmount * 0.10;
        } else if (customer.getLoyaltyPoints() > 100) {
            return orderAmount * 0.05;
        }
        return 0;
    }
    
    // เพิ่มคะแนนให้ลูกค้า - ก็ควรเป็นหน้าที่ของ Customer เหมือนกัน
    public void addLoyaltyPoints(Customer customer, double orderAmount) {
        int pointsToAdd = (int) (orderAmount / 10);
        customer.setLoyaltyPoints(customer.getLoyaltyPoints() + pointsToAdd);
    }
}
```

จะเห็น Customer มีแต่ข้อมูล แล้วพอจะทำอะไรกับลูกค้า เช่น คำนวณส่วนลด หรือเพิ่มคะแนน ต้องไปเรียก method จาก class อื่น ซึ่งมันไม่ค่อยสมเหตุสมผลเท่าไหร่

## c) ตัวอย่างโค้ดที่ Refactoring แล้ว

การแก้ไขให้ดีขึ้น:

```java
// ตอนนี้ Customer มีความสามารถในการจัดการเรื่องของตัวเองแล้ว
public class Customer {
    private String name;
    private String email;
    private String phoneNumber;
    private int loyaltyPoints;
    
    public Customer(String name, String email, String phoneNumber) {
        this.name = name;
        this.email = email;
        this.phoneNumber = phoneNumber;
        this.loyaltyPoints = 0;
    }
    
    // เหลือแต่ getter สำหรับอ่านข้อมูล
    public String getName() {
        return name;
    }
    
    public String getEmail() {
        return email;
    }
    
    public String getPhoneNumber() {
        return phoneNumber;
    }
    
    public int getLoyaltyPoints() {
        return loyaltyPoints;
    }
    
    // ย้าย logic การคำนวณส่วนลดเข้ามาใน Customer เอง
    public double calculateDiscount(double orderAmount) {
        double discountRate = getDiscountRate();
        return orderAmount * discountRate;
    }
    
    // แยก method ย่อยสำหรับหาเปอร์เซ็นต์ส่วนลด
    private double getDiscountRate() {
        if (loyaltyPoints > 1000) {
            return 0.15;  // ส่วนลด 15%
        } else if (loyaltyPoints > 500) {
            return 0.10;  // ส่วนลด 10%
        } else if (loyaltyPoints > 100) {
            return 0.05;  // ส่วนลด 5%
        }
        return 0;  // ไม่มีส่วนลด
    }
    
    // เพิ่มคะแนนจากการซื้อ - เป็นหน้าที่ของ Customer เอง
    public void earnPointsFromPurchase(double orderAmount) {
        int pointsToAdd = (int) (orderAmount / 10);
        loyaltyPoints += pointsToAdd;
    }
    
    // แลกคะแนน
    public void redeemPoints(int points) {
        if (points <= loyaltyPoints) {
            loyaltyPoints -= points;
        } else {
            throw new IllegalArgumentException("ไม่มีคะแนนเพียงพอ");
        }
    }
    
    // เช็คว่าเป็นลูกค้า VIP ไหม
    public boolean isVIP() {
        return loyaltyPoints > 1000;
    }
}

// OrderService ตอนนี้เรียบง่ายกว่าเดิมมาก
public class OrderService {
    public void processOrder(Customer customer, double orderAmount) {
        // แค่เรียกใช้ method ของ Customer
        double discount = customer.calculateDiscount(orderAmount);
        double finalAmount = orderAmount - discount;
        
        // ประมวลผลคำสั่งซื้อ...
        
        customer.earnPointsFromPurchase(orderAmount);
    }
}
```

จะเห็นความแตกต่าง ตอนนี้ Customer รู้จักจัดการเรื่องของตัวเองแล้ว ไม่ต้องให้คนอื่นมาจัดการแทน และ OrderService ก็ทำหน้าที่ของมันอย่างเดียว คือประมวลผลออเดอร์ ไม่ต้องมาจัดการเรื่องลูกค้าด้วย

## d) กรณีที่ Code Smell นี้ไม่ได้บ่งบอกถึงโค้ดที่มีปัญหา

ไม่ใช่ว่าทุกครั้งที่เจอ class ที่มีแต่ข้อมูล เราจะต้องรีบแก้ไขทันที บางครั้ง Data Class ก็ใช้ได้ตามปกติ กรณีที่ไม่ต้องแก้:

### 1. Data Transfer Objects (DTOs)
บางทีเราต้องส่งข้อมูลระหว่าง layer ต่างๆ หรือระหว่างระบบ ก็ใช้ DTO เป็นกล่องใส่ข้อมูลส่งไปส่งมา

```java
// ใช้ส่งข้อมูลระหว่างระบบ ไม่ต้องมี logic อะไร
public class CustomerDTO {
    private String name;
    private String email;
    private int loyaltyPoints;
    
    // มีแค่ Getters/Setters ก็พอ
    // เพราะมันไม่ใช่ business object จริงๆ
}
```

### 2. Value Objects
บางครั้งเราก็แค่อยากได้ตัวแทนของค่าอะไรสักอย่าง เช่น เงิน พิกัด วันที่ ซึ่งมันก็เป็นแค่ค่าล้วนๆ

```java
// แค่เก็บค่าเงินและสกุลเงิน ไม่เปลี่ยนแปลง
public class Money {
    private final double amount;
    private final String currency;
    
    public Money(double amount, String currency) {
        this.amount = amount;
        this.currency = currency;
    }
    
    public double getAmount() {
        return amount;
    }
    
    public String getCurrency() {
        return currency;
    }
    
    // ไม่มี setter เพราะเมื่อสร้างแล้วค่าไม่เปลี่ยน
}
```

### 3. Configuration Objects
เก็บค่า config ที่อ่านมาจากไฟล์หรือ environment ก็ไม่จำเป็นต้องมี behavior อะไร

```java
// เก็บค่าการตั้งค่าฐานข้อมูล
public class DatabaseConfig {
    private String host;
    private int port;
    private String username;
    private String password;
    
    // มีแค่ Getters/Setters
    // เพราะมันแค่เก็บค่า config ไม่ได้ทำอะไร
}
```

### 4. Domain Models ที่เรียบง่ายจริงๆ
บางทีมันก็เป็นแค่ข้อมูลจริงๆ ไม่มี logic ซับซ้อนอะไร

```java
// พิกัดทางภูมิศาสตร์ ก็เป็นแค่เลข 2 ตัว
public class Coordinate {
    private double latitude;
    private double longitude;
    
    public Coordinate(double latitude, double longitude) {
        this.latitude = latitude;
        this.longitude = longitude;
    }
    
    public double getLatitude() {
        return latitude;
    }
    
    public double getLongitude() {
        return longitude;
    }
    
    // บางทีมันก็แค่นี้จริงๆ ไม่ต้องมี method อื่น
}
```

### 5. ข้อกำหนดของ Framework
บาง framework มันบังคับให้เราเขียนแบบนี้ เช่น:
- JPA/Hibernate ต้องการ getter/setter
- JSON library ต้องการ POJO แบบง่ายๆ
- JavaBeans มีมาตรฐานให้ทำตาม

```java
@Entity
public class Product {
    @Id
    private Long id;
    private String name;
    private double price;
    
    // JPA ต้องการแบบนี้
    // ถึงแม้จะดูเป็น Data Class แต่เป็นข้อบังคับของ framework
}
```

## สรุป

Data Class เป็น code smell ที่เราควรระวัง แต่ไม่ได้แปลว่าต้องแก้ทุกครั้ง ต้องดูบริบทก่อนว่ามันเป็น class ประเภทไหน

**เมื่อไหร่ควรแก้:** ถ้าเป็น domain object ที่ควรมีความสามารถในการจัดการข้อมูลของตัวเอง เช่น Customer, Order, Product ที่มี business logic ให้ย้าย logic เข้ามาอยู่ใน class นั้นๆ

**เมื่อไหร่ไม่ต้องแก้:** ถ้าเป็น DTO, Value Object, Config, หรือ framework บังคับให้ทำแบบนั้น ก็ปล่อยไว้ได้ เพราะมันมีจุดประสงค์ที่ชัดเจนอยู่แล้ว

สิ่งสำคัญคือต้องเข้าใจว่า class นั้นมีหน้าที่อะไร แล้วตัดสินใจว่าควรจะแก้หรือไม่ อย่าแก้เพียงเพราะเห็นว่ามีแต่ getter/setter เยอะๆ
